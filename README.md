# 口播提词器 Android MVP

这是一个基于产品 spec V2 的 Android 竖屏 MVP，最低支持 Android 8.0（API 26）。

## DeepSeek AI 字幕校对

录制完成后，应用会先用 DeepSeek 结合当前台本校正离线语音识别结果，再生成带时间轴的字幕。若网络、接口或返回校验失败，会自动回退到原始离线字幕，不影响视频保存。

本地开发时，在被 Git 忽略的 `local.properties` 中配置：

```properties
DEEPSEEK_API_KEY=替换为新生成的密钥
```

也可以在构建进程环境中提供 `DEEPSEEK_API_KEY`。不要把密钥提交到仓库。Android APK 中的常量可被逆向提取，因此正式发布前应改为由自有后端持有密钥并代理 DeepSeek 请求。

## 在 Android Studio 中运行

1. 用 Android Studio 打开本目录。
2. 等待 Gradle Sync 完成，并确认 SDK Manager 中已安装 Android API 35 和 Android SDK Build-Tools。
3. 连接 Android 设备或创建 API 26+ 的模拟器。
4. 点击 Run，首次进入录制页时授予相机和麦克风权限。
5. 也可以使用 `Build > Generate App Bundles or APKs > Generate APKs` 输出 debug APK。

## MVP 行为

- 首页通过“口播台本 / 视频作品”双 Tab 分开管理内容；台本卡以单行标题、正文摘要、创建时间、字数和段数提高扫读效率。数据存储在 Room 数据库 `koubo.db`，未手动命名时会从台本正文自动提炼简短标题。
- 新建/编辑页支持手动输入、粘贴和选择 `.txt` 文件导入。
- 录制页默认打开前置摄像头，可通过底部的小按钮翻转镜头；前置不可用时会自动回退到后置。
- 录制页底部提供“美颜”“降噪”和镜头翻转；选中后以橙色和“· 开”明确标记，默认均关闭且录制中不可修改。
- 美颜在导出时通过 Media3/OpenGL 做可感知但克制的肤色区域平滑、提亮和暖色校正；若设备编码器不兼容会自动保住原始成片，不会因可选效果丢失录制。美颜需要逐帧重编码，因此开启后保存时间会更长。
- 降噪绑定到应用自有的 `AudioRecord` 会话，使用系统 `NoiseSuppressor` 处理同一份识音与成片 PCM；不支持该能力的设备会在页面明确提示。
- 提词卡采用较矮的顶部布局，返回操作已并入卡片头部；长按卡片可上下调整位置，点击编辑笔可修改当前台本。提词层只存在于预览 UI，不会写进输出视频。
- 视频以 H.264/AAC MP4 保存：1080p 档目标码率约 6 Mbps，避免设备默认高码率让口播视频异常膨胀。保存时会显示音视频合成、美颜处理（开启时）、写入相册三个阶段的进度和耗时。应用内副本位于 `files/recordings`，最终成片同时通过 MediaStore 发布到系统相册的 `Movies/口播提词器`；文件名继承台本标题并附带防重时间戳。相册发布失败时不会丢失应用内原片，详情页会显示失败状态并提供重试。
- 视频详情页关闭播放器自带的全画面控制蒙层，进度、后退 10 秒、播放/暂停和前进 10 秒固定放在视频下方，播放画面始终按正常亮度显示。
- 本地 sherpa-onnx 的流式部分结果用于推进逐字高亮；当前台本会作为低权重上下文热词参与小束搜索，优先消解专名、同音字、字母与口述数字，不依赖联网大模型。
- 逐字匹配会忽略标点/空白/全半角差异，兼容车牌中“6319”被识别为“六三幺九”。当前位置采用较宽松的相似度门槛，让少量同音错字也能尽快推进；向前搜索仍使用严格门槛。局部序列对齐允许跨过未识别的车牌或短句，再从后续稳定短语追上进度，同时拒绝用一两个常见字向前误跳。
- 录制时同时保存离线识音 token 的词级时间戳，成片详情可进入 Step 3“AI 字幕”：识别到的口水词均会默认标记为删除，包括“这个、然后、那么”等常见口水词；原始文字仍可逐字取消删除线恢复。每句默认生成一个克制的重点短语。
- 字幕编辑支持逐字删除/恢复、点按或横滑连续划重点、整句改写、光标处分句、与下一句合并、18sp–42sp 字号调节和三套样式。进入某行文案编辑或点选该行字块时，视频会暂停并跳到该句起点；预览会跳过已删除口水词，导出时同步裁掉对应音视频并重映射字幕时间轴；带字幕视频另存并发布到相册，原片不会覆盖。
- 字幕编辑页的“成片处理”支持导出前人声降噪和整体变速。降噪通过同一套离线滤波链路作用于播放器试听与最终 AAC 音轨；变速默认原速，开启后可在 `1.10×–1.50×` 之间按 `0.05×` 调节，画面、原声和字幕时间轴一起变化。两项参数随字幕方案保存，但导出副本会重置已物化的处理状态，避免二次编辑重复加速或重复降噪。

## 后续替换点

`domain/ReadingProgress.kt` 是逐字对齐边界，后续可以替换成 ML Kit 或服务端 ASR；录制输出、美颜导出与提词 UI 已经解耦，因此不会影响“成片不含提词文字”的约束。当前自然美颜是跨设备的轻量首版，不做瘦脸/大眼等几何变形。

## 语音跟随日志

如果真机仍停在 0%，先完整复现一次：进入录制页，开始录制，按台本连续朗读至少 15 秒，再停止。然后从 Android Studio 的 Logcat 使用 `tag:KouboSpeech` 过滤；也可以在终端执行：

```bash
adb logcat -v threadtime KouboSpeech:V RecognitionServiceImpl:I NetworkSpeechRecognizer:I SodaSpeechRecognizer:I '*:S'
```

重点保留以下行：

- `audio_config ... silenced=`：应用内识别音频是否被系统静音。
- `audio_level_db=`：持续接近 `-120` 说明设备没有向应用提供声音；正常说话应明显高于静音底噪。
- `start ... injectedAudio=` 与 `ready`：识别会话是否真正启动。
- `partial` / `results` 与 `match ... accepted=`：识别文本是否到达、匹配规则为何接受或拒绝。
- `error ... code=`：系统识别器的原始错误码、当时音量和静音状态。

日志中的 `partial` / `results` 会包含最多 32 个识别字符，提交日志前请确认其中没有不希望分享的口播内容。
